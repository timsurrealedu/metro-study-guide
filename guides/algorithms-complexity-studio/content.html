Overlapping subproblems

A naive recursive function solves the exact same subproblem over and over. Storing each finished answer in a table turns duplicate work into an instant lookup.

Optimal SubstructureA big optimal answer is built directly from optimal answers to smaller pieces.
Memoization DAGCaching turns repeated tree branches into shared pointers on a directed acyclic graph.
Fill OrderEvaluating states from smallest to largest guarantees every needed subproblem is already ready.
Example
Computing fib(5) by hand repeats fib(2) three times. Writing dp[0..5] on paper once drops the work from O(2^{n}) calls to O(n) steps.

5-Step DP Design Checklist

Follow these five steps in order on every DP exam question, checking off each step as you verify it.

  1. 1 · StateDefine what dp[\dots] means in plain English

    Name every index and exact return value (e.g., max sum ending at i, or best value using items 1..i within capacity c).

  2. 2 · RecurrenceWrite the transition formula over smaller states

    List every valid choice (take vs. skip, split point k, or predecessor u) and combine via \min, \max, or \sum.

  3. 3 · Base CasesAnchor the smallest subproblems

    Set length-0 strings, capacity 0, single-element intervals [i, i], or unreachable states (\pm\infty).

  4. 4 · Fill OrderOrder loops so dependencies come first

    Choose left-to-right (1D), right-to-left (rolling 0/1), diagonal length l = 2 \dots n (interval), or increasing subset size \vert S\vert (bitmask).

  5. 5 · Cost & TracebackState time, space, and parent pointers

    Multiply number of states by work per state, and store parent[i], s[i,j], or arrows to reconstruct the actual solution.

4-Step NP-Completeness Proof Template

Check off all four mandatory steps whenever proving a language B is NP-complete on an exam.

  1. Step 1 · B ∈ NPState the certificate and polynomial verifier

    Define a poly-size witness y and show a deterministic algorithm verifies (x, y) in O(n^{k}) time.

  2. Step 2 · Pick Source AChoose a known NPC problem A (A \le_{P} B)

    Never reduce B \le_{P} A! Pick \text{3-SAT}, \text{VERTEX-COVER}, or \text{HAM-CYCLE} to match B's structure.

  3. Step 3 · Construct F(x)Describe the polynomial-time reduction mapping

    Show how to build instance F(x) from x in O(n^{k}) time and space (gadgets, thresholds).

  4. Step 4 · Two-Way ProofProve both x \in A \Rightarrow F(x) \in B and F(x) \in B \Rightarrow x \in A

    Forward turns a solution of A into a witness for B; backward extracts a valid solution of A from B.

Reducing B ≤ₚ A in the wrong direction
Showing B \le_{P} A only proves B is at most as hard as A. To prove B is hard, reduce known hard A \le_{P} B.
